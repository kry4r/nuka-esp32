首次刷写前已独占打开设备端口，完整读取 16 MiB 原厂 Flash，并核验文件长度与 SHA-256。备份及原始串口日志仅保存在 git 忽略目录；报告不包含设备端口、MAC、主机名或部署值。

自动刷入 bootloader、分区表、OTA 初始数据、应用和资源 bank 0，各段写入均通过 esptool 哈希验证。没有整片擦除，没有烧录 eFuse，没有启用 Secure Boot 或 Flash 加密。

启动日志已确认 16 MiB Flash、8 MiB Octal PSRAM、240 MHz CPU。首次故障为 I2C 两线均低、四地址超时。硬关机重上电后两线释放，四地址应答，设备完成启动。后续 USB 写入错误在更换物理 USB 口后消失，重新刷写各段哈希校验通过。维护者已确认新画面刷新。

原始证据存于忽略目录，问题修复后本报告继续更新，不以编译通过代替硬件验收。

显示诊断：QSPI 40 MHz，内部 DMA 双缓冲，偶数 rounder 保持；首 DMA 区域为 (0,0)–(479,47)。经维护者同意关闭 LVGL FAST_MEM IRAM 后，启动内部空闲内存为 157,027 B、最低值 26,432 B。诊断临时保持 USB 常亮，不能把此诊断当作睡眠功耗验收。

完整系统启动复测：应用单独刷写通过哈希验证。首次捕获到日志初始化中止；读取完整 storage 分区并离线挂载 LittleFS，确认其中只有长度为 0 的 `/log`。旧实现先创建最终文件，断电可能在提交头部前留下空文件；已改为完整写入临时文件、关闭并原子重命名，仍在初始化错误时中止。经维护者授权，备份后仅清除 storage，未清除 NVS、Vault 或资源。随后应用切走原生 USB 串口，但 CDC 尚未枚举，需读取后半启动日志定位，不能判为 USB 验收通过。

USB 睡眠约束：ESP-IDF/esp_tinyusb 的 USB OTG 唤醒配置仅适用于 HS UTMI PHY，ESP32-S3 的 FS PHY 不支持该唤醒源。实现按 AXP 的 VBUS 状态持有 `ESP_PM_NO_LIGHT_SLEEP`，拔线后释放，仍允许熄屏、关闭渲染和调低 Wi-Fi 省电级别。USB 插电状态不能用于验证脱机 light-sleep 电流；此项是功能约束，未进行功耗调优。

完整固件故障：维护者随后观察到新表盘反复闪烁，组合键恢复菜单无法打开。当时未取得这轮启动的串口或持久日志，因此不能把现象直接判为重启、过热关机或 USB 驱动错误。多轮被动观察未捕获到端口。已编译使用当前 NVS 布局、常亮并保留原生 USB 串口的最小诊断应用；诊断不启动电源策略、PMU 轮询、TinyUSB 或网络。没有为此清除其他分区，也没有把旧布局诊断固件直接刷回。

恢复进展：维护者断开电池并确认正确的 BOOT 键后，ROM 连接稳定。先读取 8 KiB OTA 元数据，确认 `ota_0` 为 VALID，再仅写入当前布局诊断应用，哈希验证通过；额外只读备份整块 storage。诊断启动后连续采集 65 秒，只有一条启动记录、一次持续 USB 连接、无 panic；运行时间从 1,523 ms 增至 64,381 ms，flush 从 0 增至 254，芯片温度从 40.5°C 降至 38.7°C，内部空闲内存稳定在约 179,719 B。此结果只证明该诊断路径稳定，不能证明完整系统、触摸、三键或睡眠验收通过。

维护者确认恢复后画面稳定、不再闪烁。进一步运行原生 USB 分段版本：启动实际 UI、日志、电源、输入与 PMU 任务，暂不启动 TinyUSB 或网络，常亮只修改 RAM。连续观察 70 秒，一次持续串口连接，无 panic；flush 从 240 增至 636，内部空闲为 100,147 B，历史最低为 12,152 B。步骤 9 至后续标记之间约有 19.3 秒停顿，原因待定位。以上内存尚未达到完整系统验收线，不能作为 M1 或后续里程碑通过。

静态审计确认：显示 DMA 与电源任务的亮度命令共享同一 SPI 设备，ESP-IDF 要求跨任务同步。已添加面板互斥，覆盖绘图提交至 DMA 完成及亮度、睡眠、唤醒命令。此修复尚不能认定为原先闪烁的根因；继续使用保留原生 USB 的网络分段版本采集日志。

网络分段结果：未启动 TinyUSB，启动至 Wi-Fi 时明确复现 `esp_wifi_init()` 返回 `ESP_ERR_NO_MEM`。驱动原计划分配 16 个静态接收缓冲，实际只分配 13 个，随后初始化的 `ESP_ERROR_CHECK` 触发 abort；原生串口记录重启原因变为软件 panic。因此至少已确认一条启动重启路径，不能再将全部现象归因于 USB 枚举。已自动恢复上述最小诊断应用，仅覆盖应用分区，哈希验证通过；20 秒连续采集无 panic。完整系统暂停刷写，先修正内部 RAM 预算并逐步复测。

内存修复后重新验证完整系统：应用单独刷写通过哈希校验，CDC 与两个 HID 接口均枚举成功。重复 `info`、`diag.info`、带 50 层未知字段的请求及日志分块转储，并连续观察 45 秒，uptime 单调增长、无重启；内部空闲约 102 KB。USB 临时缓冲移至内部堆后，4 KiB USB 任务栈历史余量从 144 B 增至 1,712 B。详细分配与任务预算见 [fw-memory.md](fw-memory.md)。尚未配网，不能据此判定完整内存验收通过；触摸、三键、睡眠与 M1 其他人工项仍待验证。
