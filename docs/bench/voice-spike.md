# FW2-05 语音硬件 spike

2026-10-24。状态：**首轮失败，已停止自动比较；正在拆分排查播放与采音，音频方案未冻结。**

## 原型与输入

- ESP-IDF 5.5，ES8311 播放、ES7210 MIC1 / MIC2 采音，共享板载 I²C 总线互斥锁。
- I²S0 全双工，16 kHz / 16 bit / 双声道总线；上传候选 PCM 取第一路麦克风，播放时将单声道复制到左右槽。
- DMA 缓冲由 ESP-IDF I²S 驱动分配在内部 RAM；每个方向 3 个描述符、每描述符 160 个双声道帧。5 秒录音与解码输出只存于易失 PSRAM，不保存音频文件或写入对话日志。
- ES8311 初始化期间功放保持关闭，首段静音入队后才启用功放；结束后先关闭功放，再停编解码器、I²S 和 ALDO1。
- `CONFIG_NUKA_AUDIO_SPIKE` 默认关闭。开启后，联网 10 秒后仅运行所选诊断一次；阶段 1 仅播放 500 ms 合成音，确认可听后才进行阶段 2 的声道统计、阶段 3 的单轮 PCM、阶段 4 的 PCM / Opus 对比。该诊断不定义或发送新的业务协议消息。
- Opus 对照为 16 kHz / 单声道 / 60 ms、24 kbit/s、复杂度 5。最后不足 60 ms 的部分补零；统计的 Opus 包含补齐后的 5.04 秒。

## 测量方法

每次采集记录当前内部空闲的最小值，而不是沿用启动时的历史最低值。FreeRTOS 运行时统计分别报告本任务运行时间、双核空闲任务的增量、任务栈历史余量；录音和回放的阻塞时间计入整轮墙钟时长。Opus 编码和解码另用 `esp_timer` 计时。CPU 为整轮平均，不等同于瞬时峰值。

首次只读基线：设备 `uptime=511 s`、内部空闲 **109,851 B**、PSRAM 空闲 **8,178,672 B**，重启原因 `power_on`。这只是开始 spike 前的一次观测，不替代浸泡测试。

首轮 PCM 的样本峰值仅 **37 / 32768**，维护者反馈未听到语音。这一轮只证明驱动调用返回完成，**没有通过录音或播放验收**。Wi-Fi 已连接，但 Hub TCP 连接持续失败，因此数据也不代表有效 WS 会话负载。

随后 Opus 编码触发 `audio_spike` 任务栈溢出并重启。组件构建已经启用 `FIXED_POINT=1`、`DISABLE_FLOAT_API` 和 `USE_ALLOCA`；不能把失败归为浮点配置。重启后的一次诊断记录历史内部空闲最低值 **52,188 B**，低于会话门槛；此历史值不能定位到单个编码步骤。该镜像的上电自动重跑会再次触发失败，已让设备保持 ROM 下载模式停止循环，后续先使用不录音、不调用 Opus 的短音阶段。无声轮与崩溃轮不能用于冻结 C2-02。

静态排查修正：ES7210 `enable()` 会重新选择通道并覆盖此前设置的增益；原型已将 24 dB 增益设置移到 `enable()` 之后，并明确解除麦克风静音。声道探针分别按 16 / 32 bit 读取两槽的峰值、RMS、直流偏置及有效位掩码，同时读回实际格式与增益。它尚未完成真机复测，不能据此声称采音问题已解决。

下一轮 Opus 诊断将使用 64 KiB PSRAM 任务栈，TCB 与 I²S DMA 仍保留在内部 RAM，使用 ESP-IDF 的 `xTaskCreatePinnedToCoreWithCaps` / `vTaskDeleteWithCaps` 配对释放。此改动只为取得有效测量，尚无栈余量、速度或内存验收结论；普通镜像仍默认关闭 spike。

## 带宽与协议边界

PCM 的理论原始音频速率为 32,000 B/s；独立 base64 编码时约 42,667 B/s，另加 JSON / WS / TCP / TLS 开销。此为格式计算，**不是 WS 吞吐实测**。Opus 24 kbit/s 是编码器设置，不是实测网络速率。

尚无冻结的语音传输契约，原型没有私自向 Hub 增加音频字段、消息或二进制帧。实际 WS 音频吞吐、Wi-Fi 省电对网络时延的影响，需要在 C2-02 确定消息格式后联调补测。
