完整系统通过 `info`、`diag.info`、含 50 层未知数组的 `info` 请求及 `diag.dump_log`。后者按序重建 3,141 B 日志，记录了实际 USB 驱动安装、Wi-Fi 初始化及第 12 步启动。重启后的持久化留存尚待复核，当前转储来自内存环。未配网基线不能代表关联 Hub、浏览全部卡片、Vault 解锁、OTA 或浸泡测试后的内存。

修复保留 QSPI 40 MHz、两个 480×48×2 B 内部 DMA 缓冲和偶数 rounder。面板操作用同一互斥锁串行化，绘图持锁直到 DMA 完成。日志队列负载、64 KiB 日志环、600 点电池历史、普通 JSON、NVS 元数据和受 SDK 支持的网络 BSS 放在 PSRAM；任务栈、Vault 明文、CDC 输入及 mbedTLS 分配留在内部 RAM。所有修改均为功能内存预算措施。

日志磁盘格式保持不变，严格读入头部和整个环；运行时先更新 PSRAM 环，以不超过 1 秒的收集窗口合并队列，再连续写头部与环数据。此举避免每条日志先写尾部、再回写头部造成的 LittleFS 多次 copy-on-write。突然掉电可能丢失尚未持久化的一批日志；文件系统写入耗时另计。`diag.dump_log` 只复制内存环。

早期历史最低值不能直接当作同时剩余内存：ESP-IDF 在建立内部 reserve 池时，先从原堆分配、再将同一范围注册为新堆；各堆分别累计的历史最低值相加，可能对应不同时间。没有重置或隐藏该指标，原始读数均保留。reserve 收敛依据是绘图 DMA 在网络启动前分配、普通数据优先 PSRAM，以及后续小块内部分配需求。

首次完整 CDC 手验后，USB 4096 B 栈的历史余量仅 144 B。将临时 token 和 RX 缓冲移至显式内部堆后，重复深层未知字段、日志转储及 45 秒运行，历史余量增至 1,712 B；转储按序重建 3,204 B，USB 未重启。Vault、配网和大体积导入导出的实际水位仍待验证。

软件进入下载模式仍有待修复的问题：释放 TinyUSB 后可进入 ROM 并读取寄存器，但从该模式返回应用仍未通过。普通软件重启则已验证 CDC 自动恢复；加入 `fsync` 后，受控重启前后日志前缀保留，启动标记增加，持久化留存已通过。具体问题以 [联调报告](e2e-report.md) 为准。

真实联网复测（2026-10-18）：配网后原版本空闲约 94,499 B，系统事件任务历史余量仅 200 B，并发生 panic。依据实际水位调整 swdraw 8192→4096 B、mDNS 4096→2048 B、esp_timer 3584→2048 B，同时扩大 sys_evt 2304→4096 B；Wi-Fi 静态 TX 缓冲 4→2。普通联网后 22 个任务栈合计 78,848 B，OTA 再增加 6144 B，其他按需任务峰值仍待实测。内部 DMA 绘图缓冲与敏感数据位置不变。

通过真实 OTA 安装上述配置及 Vault 递归修复后，CDC uptime 从 8 秒连续增长至 53 秒，联网稳定后的内部空闲为 103,851 B，PSRAM 约 8.18 MB；USB 余量 1680 B、sys_evt 1984 B、mDNS 556 B、swdraw 2360 B、esp_timer 1572 B。仍保留历史最低指标 61,244 B，不据此宣称峰值通过。启动/OTA 确认期间一次当前空闲为 97,539 B，全部卡片、Vault 和 OTA 同时运行的内存验收仍未通过。
