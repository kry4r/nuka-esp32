## 2. 规格增补

### 2.1 顶部居中标题与状态栏（D27）
- 状态栏仍在 `ui/nav.c`，高 40，垂直位置不变。屏幕四角是圆角，状态栏左右两端各向内收，内容只放在离屏幕边缘 ≥ 48px 的区域内（实机确认可见边界后定值）。
- 布局：
  - **正中**：页面标题，22px，最大宽度约 220px，过长时省略号截断；
  - **左侧**：当前时间（22px，表盘页不显示）和连接状态图标（离线时变成"离线"小标签）；
  - **右侧**：勿扰、充电、电量（图标 + 百分比）。
- 返回图标不再放在状态栏里，L1 的返回提示放到标题左边的一个小箭头上，与标题一起居中。
- 主页的两面（时钟、表情）不显示标题，只保留最小化的图标，表情面在全屏动画时可以只留电量。
- 标题文字来自 `tr("app.<id>")`，中英文都要检查截断。

### 2.2 AI 余额页重做
在**现有 `ai` 视图模型字段**内重新设计；如果确实缺字段，列入 C2-01 的契约批次，不在实现中自行约定。
- **L0**：
  - 顶部：provider 图标、账号脱敏标签、状态标签（正常 / 冷却中 / 需重新登录 / 熔断）；
  - 中部：5 小时窗口与周窗口的双环，环内显示主百分比，环下显示恢复倒计时；
  - 底部一排三个指标：今日请求数、Token 数、失败率；
  - 有多个账号时，用 pager 圆点表示，BOOT 长按切换。
- **L1**：
  - 账号列表，每行一个迷你双环、状态和恢复时间；
  - 今日用量明细（按模型的 Top 3，前提是 VM 中已有该数据）；
  - "刷新"操作（`ai.refresh`，限流）。
- 视觉：数值滚动动画沿用 `ANIM_*`；冷却、熔断、需重新登录分别用主题中的 warn / err 色，不用大面积亮色块。
- 余额接近耗尽时，表情面也要有反应（见 §2.4）。

### 2.3 主页双面与新的 Key3 映射（D21、D26）
- L0 卡片轮播：`[主页（时钟面 | 表情面）]`、主机、服务器、AI 余额、Buddy、番茄钟、媒体、天气、Vault、设置。**删除桌宠卡**，原 `pet` 视图模型主题保留，作为表情面情绪的数据源。
- 主页记住上次显示的是哪一面；默认面可由 Hub 的 `cfg.home_face` 下发（C2-01）。

新的 Key3 映射（只列出与 SPEC §6.9.3 不同的情境）：
| 情境 | Key3 短按 | Key3 按住 | Key3 双击 |
|---|---|---|---|
| L0 主页 | 在时钟面和表情面之间切换 | **说话**（按住期间录音，松开发送） | 跳到 Buddy 卡 |
| L0 其他卡片 | 回到主页（显示上次的那一面） | **说话** | 跳到 Buddy 卡 |
| L1 详情页 | 返回 L0 | **说话** | — |
| 助手正在回答 | 打断播放并回到空闲 | 打断后立即开始新一轮说话 | — |
| 权限审批 sheet、Vault、PIN 输入、恢复菜单 | 不变 | 不变（**说话被禁用**） | 不变 |

- 按住判定：Key3 按下时**立即开始采音**，写入预录缓冲；按住满 400ms 才进入"聆听"状态并开始上传；不到 400ms 就松开，丢弃录音，按短按处理。这样既不丢开头的字，也不影响短按。
- 按住超过 30s 自动结束本轮（上限由契约给出）。
- 说话会把屏幕唤醒到亮屏，并在会话期间暂停熄屏计时。
- 原 Key3 长按的"切换勿扰"移到快捷面板（BOOT 长按主页打开）；`key3_long` 仍可配置回旧的快捷动作，此时说话功能关闭。
- 设备未连上 Hub，或 Hub 没有启用助手时，按住 Key3 只让表情面做一个"听不见"的动作，并显示一行提示。

### 2.4 Nomi 式表情面（D26）
- **形态**：纯黑底，两只牛油果绿的发光圆角矩形眼睛（外圈一层低亮度光晕），没有嘴；情绪只靠眼睛的宽高、圆角、上下眼睑遮挡、视线位置、眨眼和整体弹跳来表达。
- **全部用 LVGL 基础对象绘制**，不用位图资源；动画只改动两只眼睛所在的局部区域（每只约 120×160），不做全屏运动、全屏半透明或模糊（NFR-2、无 TE 引脚）。
- **状态表**（数据来源：本地状态 + `pet` 主题 + 语音会话状态 + 其他 VM）：

| 状态 | 触发 | 表现 |
|---|---|---|
| 空闲 | 默认 | 随机眨眼（3–7s）、视线缓慢漂移、偶尔小幅弹跳 |
| 注意 | 有待审批的请求 | 眼睛睁大并看向 Buddy 方向，轻微脉冲 |
| 聆听 | 按住 Key3 说话 | 眼睛略微放大，随麦克风音量上下起伏 |
| 思考 | 等待 ASR / LLM | 视线上移，左右来回扫动 |
| 说话 | 播放 TTS | 眼睛随 TTS 音量包络轻微弹跳 |
| 开心 / 庆祝 | 番茄钟完成、任务成功、被摸 | 弯月眼，连跳两下 |
| 忙碌 | 有 Agent 会话正在运行 | 眯眼、专注 |
| 担心 | 服务器 critical 告警、AI 余额 <10% | 眉形倾斜（用眼睑遮挡模拟） |
| 饿了 | AI 余额耗尽或熔断 | 眼睛下垂、偶尔看向 AI 卡方向 |
| 犯困 | 夜间、即将熄屏 | 眼睑缓慢下落，眨眼变慢 |
| 充电 | 充电中且空闲 | 闭眼，眼间显示一个小闪电 |
| 晕 | IMU 检测到摇晃 | 螺旋眼 1.5s |
| 离线 | 与 Hub 断开 | 眼睛变成两条横线，暗色 |
| 错误 | 语音会话失败 | 眨两下，下方显示一行原因 |

- **触摸**：点一下会眨眼并看向触点；在表情面上下滑动仍然是原有手势，不另做。
- **字幕**：说话时在眼睛下方显示一到两行字幕（先显示识别出的问题，回答时显示回答的开头）。中文字体子集只有约 3500 个常用字，缺字显示成占位符；字幕只是辅助，主要信息靠语音和表情。
- **功耗**：熄屏和低电模式下停止全部动画；亮屏空闲时把动画帧率降到能维持眨眼和漂移的最低值，FE 在 FE2-04 中测量并写入报告。

### 2.5 语音助手（D21–D25）
**数据流**：
```
设备 Key3 按住 ──麦克风（ES7210）──> 上行音频帧 ──WS──> Hub
Hub：ASR（本地 sherpa-onnx / Cloudflare / OpenAI 兼容）
   → LLM（OpenAI 兼容，流式，function calling）⇄ 工具（nuka 内置、MCP、搜索）
   → TTS（Edge-TTS / Cloudflare / OpenAI 兼容，分句流式合成）
Hub ──下行音频帧 + 会话状态 + 字幕──WS──> 设备 ──ES8311 + 功放──> 扬声器
```
- **音频格式**：由 FW2-05 的 spike 在两种方案中选定，结论写进 `docs/bench/voice-spike.md`，再由 C2-02 写进契约：
  - 方案 P：16kHz、16bit、单声道 PCM，上行约 32KB/s；
  - 方案 O：Opus，16kHz、60ms 一帧（与小智相同），上行约 2–3KB/s，但设备上要跑编码器，Hub 上要解码（libopus，BSD）。
- **会话**：一次按住 = 一轮。Hub 为每台设备维护最近 N 轮模型上下文，同时永久保存完整对话（Q6、§2.8）。设备在任何时候都可以发"停止"打断。
- **延迟目标**：松开 Key3 到听到第一个字 ≤ 2.5s（局域网、在线 ASR、流式 LLM、分句 TTS）；本地 ASR 允许 ≤ 4s。这是体验目标，不是验收硬指标，由 INT2 实测记录。
- **工具**（D25）：
  - **查询**：主机状态、服务器状态与告警、AI 余额、Agent 会话、天气、通知、时间；
  - **控制设备**：番茄钟开始 / 暂停 / 重置、媒体播放 / 暂停 / 上一首 / 下一首、屏幕亮度、勿扰、定时提醒（由 Hub 到点推送通知）；
  - **外部 MCP 服务器**：支持 stdio 和 Streamable HTTP 两种接入，在 Web 上逐个添加，逐个工具勾选启用；
  - **联网搜索**：可选 SearXNG（自建）或带密钥的搜索 API，在 Web 上选择；
  - 写操作类工具（MCP 中被标记为写操作的、发通知、改设备设置）要在设备上确认（Q8），只读工具直接执行。
- **安全**：
  - 所有密钥（LLM、ASR、TTS、搜索、MCP 的令牌）都存在 Hub 的钥匙串，按名称引用；
  - 设备只能用自己的 device 令牌发起会话；
  - Web 的测试对话只对 local / lan 区域开放；
  - 日志中不写音频内容，对话文本只写进 Q6 规定的对话记录，可以关闭；
  - Edge-TTS 用的是非官方接口，引导中要写清楚它可能失效，并给出备选。
- **依赖**（全部放进可选依赖组 `nuka-hub[voice]`，不装就不启用助手）：

| 依赖 | 用途 | 许可证 | 备注 |
|---|---|---|---|
| sherpa-onnx | 本地 ASR | Apache-2.0 | 模型文件首次使用时下载，不进仓库 |
| edge-tts | 免费 TTS | GPL-3.0（以 THIRD_PARTY 核实为准） | 与 AGPL 兼容 |
| mcp（官方 Python SDK） | MCP 客户端 | MIT | |
| libopus 绑定（仅方案 O） | Opus 编解码 | BSD | |
| tomlkit | 表单写回 TOML 时保留注释 | MIT | BE2-06 用，不属于 voice 组 |

- **Cloudflare Workers AI 候选模型**（2026-10 查到的目录，开工时再核对）：
  - ASR：`@cf/openai/whisper-large-v3-turbo`（支持中文）、`@cf/openai/whisper`、`@cf/deepgram/nova-3`（中文支持待验证）；

### 2.6 Web：表单化配置与小智式助手页（D28）
- **表单化**：Hub 从 pydantic 配置模型导出 JSON Schema，Web 按 schema 生成表单（分组、说明文字、枚举下拉、必填校验）；保存时用 tomlkit 写回 `config.toml`，保留用户的注释和顺序；密钥字段只写不读，显示"已设置 / 未设置"。
- **覆盖范围**：Hub 基本设置、采集器、服务器数据源、推送 hook 与告警规则、AI 配额（CPA / CPAMP）、媒体、天气、公网访问、助手（下一节），以及设备（§2.7）。
- **原 TOML 编辑器**保留在"高级"标签里，行为不变（保存失败时显示行号）。
- **助手页**（参照小智的后台）：
  - 角色：名字、人设模板（几个内置模板 + 自定义 system prompt）、回答语言、回答长度偏好；
  - 模型：`base_url`、模型名（可以从 `/v1/models` 拉取列表选择）、密钥名、温度；
  - 语音：ASR 提供方与模型、TTS 提供方与音色、语速，提供"试听"按钮；
  - 工具：内置工具开关、MCP 服务器列表（添加、测试连接、逐个工具勾选）、搜索提供方；
  - 测试对话：文字输入，显示工具调用过程，可选在浏览器里播放 TTS；
  - 对话记录：查看、清空、关闭（Q6）。
- 仍然是原生 ES modules，不用构建工具，不用 CDN；只做深色主题；手机宽度可用。

### 2.7 USB 即插即配与联网后的设备设置（D29）
**USB 即插即配流程**：
1. Hub 后台每 2s 枚举一次串口，按 VID/PID 找到 nuka 设备，再用 CDC 的 `info` 确认（同时修正 PROTOCOL §4.1 中按产品名识别的描述）。
2. 发现未配对或未配网的设备时，Web 的设备页弹出"发现新设备"，显示型号、固件版本、MAC 后 4 位。
3. 用户点"开始配置"：
   - Hub 通过新的 CDC 命令 `wifi.scan` 让设备扫描周围的 2.4GHz 网络，列在 Web 上，按信号排序；
   - 用户选网络、填密码（也可以手动输入隐藏网络）；
   - Hub 地址自动填入 Hub 本机的局域网地址和 mDNS 名，可修改。
4. Hub 生成 device 令牌，通过 `prov.set` 下发；设备上弹出"允许这台电脑配置本机？"的确认 sheet，**BOOT 按住 1s 确认**（物理在场即授权，取代手输 6 位配对码）。
5. 设备连 Wi-Fi、连 Hub；Web 实时显示每一步的进度和失败原因（密码错误、找不到网络、Hub 不可达）。
- 这条流程只对 local / lan 区域开放，并且每一步都要设备在 USB 上；`nuka pair` 命令行改为复用同一套流程。

**联网后的设备设置**（Web 设备页 → 设备详情，经 WS `cfg` 下发）：
- 显示：亮度、变暗与熄屏时间、语言、主页默认面；
- 按键：`key3_long`、Key3 双击目标、表盘样式切换；
- 声音与助手：音量、是否启用助手、提示音；
- Wi-Fi：已保存网络的列表、增删网络（受 Q4 限制）；
- 维护：重启、触发 OTA 检查、导出诊断信息。
- 设备本地改过的项不被 Hub 覆盖（沿用现有 `cfg` 规则），Web 上标注"设备本地已修改"。

### 2.8 Pi 助手、永久记忆与服务器（D30–D32）
- **运行边界**：Python Hub 保留网络、鉴权、ASR / TTS、工具权限和 SQLite；Pi agent-core / pi-ai 作为本机 stdio 子进程承接 OpenAI 兼容模型的流式调用与工具循环。子进程没有独立监听端口，不载入编码代理的文件、终端、扩展或个人配置。
- **权限**：Pi 只能获得 Hub 明确注册的工具；每次执行仍由 Hub 校验启用列表和设备确认，模型和 MCP 的权限提示不能替代此闸门。中止同时取消模型、待确认工具与播放。
- **永久记录**：SQLite WAL 中按设备 / 会话 / 消息标识保存完整的用户文本、助手文本和工具生命周期；写入幂等，重启恢复。最近 20 轮只控制模型输入，不删除存档；工具调用与结果必须成组保留。原始音频默认仅在内存中流转。
- **长期记忆**：另表保存用户明确要求记住的事实，带来源消息、创建 / 更新时间；检索按设备隔离并限制条数和长度。记忆作为不可信资料加入上下文，不能改写 system 指令或工具权限。先用 SQLite 检索，不引入向量数据库和后台自动推断。
- **数据控制**：Web 可分页查看记录、导出 JSONL、删除会话或记忆、关闭记录；关闭后不写入新数据，清空才删除历史。备份通过 SQLite 在线备份 API 创建一致快照，恢复时显式停服验证；不直接复制正在写入的数据库文件。
- **上传**：Web 可上传需要保存在服务器的文档、模型和附件；文件保存在数据目录，不在代码目录。服务端生成存储标识、限制大小、校验路径与归属，下载强制附件，不自动执行。Vault 数据仍只走设备 USB，不进入此接口。
- **远程配置**：服务器只监听回环服务端口，cloudflared 连接该端口。公网配置必须同时通过 Cloudflare Access 身份校验与 Hub admin 会话 / CSRF，部署显式开启；普通公网请求仍受区域矩阵限制。`/hook/*` 和 Web 审批始终返回 404。不能把 CF 流量伪装成 lan 来开放接口。
- **本机 USB**：远端服务器无法枚举用户电脑的 USB；保留本机 Hub 配网入口，将服务器 `wss://` 地址与 device 令牌通过 USB 写入设备。后续配置在服务器网页进行，Wi-Fi 密码变更仍要求本机串口。
- **依赖**：Pi 核心包单独锁定 npm 版本，仅在启用助手时需要 Node；Hub 其余部分继续由 uv 管理。新增依赖和许可证写入 THIRD_PARTY。
